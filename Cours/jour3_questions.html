Questions & Réponses - Routing & Requêtes HTTP

🧭 PARTIE 1 : ROUTING ET NAVIGATION

Le routing permet de créer une SPA (Single Page Application) avec plusieurs "pages" sans recharger le navigateur.

Fonctionnement :
  • L'URL change (ex: /home → /produits)
  • Angular affiche un composant différent
  • Pas de rechargement de page
  • Navigation instantanée
Avantages :
  • ✅ Expérience utilisateur fluide
  • ✅ Pas de latence réseau
  • ✅ URLs partageables
  • ✅ Navigation avant/arrière du navigateur
  • ✅ SEO possible avec SSR
export const routes: Routes = [
  { path: 'home', component: HomeComponent },
  { path: 'produits', component: ProduitsComponent }
];

// URL change : /home → /produits
// Angular affiche ProduitsComponent
href (HTML standard) :
  • Recharge toute la page
  • Perte de l'état de l'application
  • Latence réseau
  • ❌ Ne pas utiliser dans Angular
routerLink (Angular) :
  • Navigation sans rechargement
  • Conservation de l'état
  • Navigation instantanée
  • ✅ Toujours utiliser pour navigation interne

<a href="/produits">Produits</a>


<a routerLink="/produits">Produits</a>
<a [routerLink]="['/produit', id]">Détail</a>
⚠️ Important : N'utilisez href que pour les liens externes (ex: href="https://google.com")
1. Paramètres de route (dans l'URL) : 
// Routes
{ path: 'produit/:id', component: ProduitDetailComponent }

// Navigation
<a [routerLink]="['/produit', 123]">Produit 123</a>
this.router.navigate(['/produit', 123]);

// URL résultante : /produit/123
2. Query params (après ?) : 
// Navigation
<a [routerLink]="'/produits'" 
   [queryParams]="{ category: 'electronics', sort: 'price' }">
  Électronique
</a>

this.router.navigate(['/produits'], {
  queryParams: { category: 'electronics', sort: 'price' }
});

// URL résultante : /produits?category=electronics&sort=price
3. Accéder aux paramètres : 
// Méthode 1 : Observable (si paramètres changent)
route.paramMap.subscribe(params => {
  const id = params.get('id');
});

route.queryParamMap.subscribe(params => {
  const category = params.get('category');
});

// Méthode 2 : Snapshot (accès ponctuel)
const id = route.snapshot.paramMap.get('id');
const category = route.snapshot.queryParamMap.get('category');

Le lazy loading charge les modules de route à la demande (quand l'utilisateur navigue vers la route).

Sans lazy loading :
  • Tout le code chargé au démarrage
  • Bundle initial lourd
  • Temps de chargement long
Avec lazy loading :
  • Code chargé à la demande
  • Bundle initial léger
  • Démarrage rapide
export const routes: Routes = [
  { path: 'home', component: HomeComponent },
  
  // ✅ Lazy loading
  {
    path: 'admin',
    loadChildren: () => import('./routes/admin.routes')
                        .then(m => m.adminRoutes)
  }
];

// admin.routes.ts
export const adminRoutes: Routes = [
  { path: '', component: AdminComponent },
  { path: 'users', component: UsersComponent }
];
✅ Résultat : Le code de l'admin n'est chargé que quand on navigue vers /admin. Gain de 30-50% sur le bundle initial !

Un Guard protège l'accès aux routes (authentification, permissions, etc.).

Types de guards :
  • CanActivate : Contrôler l'entrée d'une route
  • CanDeactivate : Confirmer avant de quitter
  • CanMatch : Charger ou non un module lazy
  • Resolve : Charger des données avant affichage
Exemple CanActivate : 
// Guard
export const authGuard: CanActivateFn = (route, state) => {
  const authService = inject(AuthService);
  const router = inject(Router);

  if (authService.isAuthenticated()) {
    return true; // Accès autorisé
  }

  router.navigate(['/login']);
  return false; // Bloqué
};

// Routes
export const routes: Routes = [
  { 
    path: 'admin', 
    component: AdminComponent,
    canActivate: [authGuard] // ✅ Protégé
  },
  { path: 'login', component: LoginComponent }
];
Exemple CanDeactivate : 
export const unsavedGuard: CanDeactivateFn<any> = (component) => {
  if (component.hasUnsavedChanges()) {
    return confirm('Modifications non sauvegardées. Quitter ?');
  }
  return true;
};
paramMap (Observable) :
  • Écoute les changements de paramètres
  • Réactif
  • Idéal si l'utilisateur peut changer l'ID sans quitter la page
snapshot (Accès ponctuel) :
  • Accès immédiat aux paramètres
  • Non réactif
  • Plus simple
  • Idéal si les paramètres ne changent pas
// ✅ paramMap - si paramètres peuvent changer
route.paramMap.subscribe(params => {
  const id = params.get('id');
  this.loadProduct(id);
});

// ✅ snapshot - accès ponctuel
ngOnInit() {
  const id = this.route.snapshot.paramMap.get('id');
  this.loadProduct(id);
}
💡 Règle : Utilisez paramMap si vous restez sur le même composant avec des params différents. Sinon, snapshot suffit.

Nouvelle API qui injecte automatiquement les paramètres de route comme @Input() dans le composant.

Avant (sans bindToComponentInputs) : 
// Route
{ path: 'produit/:id', component: ProduitComponent }

// Composant
export class ProduitComponent {
  private route = inject(ActivatedRoute);

  ngOnInit() {
    this.route.paramMap.subscribe(params => {
      const id = params.get('id');
      // ...
    });
  }
}
Après (avec bindToComponentInputs) : 
// Route
{ 
  path: 'produit/:id', 
  component: ProduitComponent,
  bindToComponentInputs: true // ✅ Active l'injection
}

// Composant - beaucoup plus simple !
export class ProduitComponent {
  id = input<string>(''); // Paramètre injecté automatiquement
  
  // Pas besoin d'ActivatedRoute !
}
✅ Avantages : Plus simple, type-safe, moins de code, meilleure performance.
🌐 PARTIE 2 : REQUÊTES HTTP
1. Configurer HttpClient : 
// main.ts
import { provideHttpClient } from '@angular/common/http';

bootstrapApplication(AppComponent, {
  providers: [
    provideHttpClient()
  ]
});
2. Créer un service : 
@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);
  private apiUrl = 'https://api.example.com/users';

  getUsers(): Observable<User[]> {
    return this.http.get<User[]>(this.apiUrl);
  }

  getUser(id: number): Observable<User> {
    return this.http.get<User>(`${this.apiUrl}/${id}`);
  }
}
3. Utiliser dans un composant : 
@Component({...})
export class UsersComponent implements OnInit {
  userService = inject(UserService);
  users = signal<User[]>([]);
  isLoading = signal(true);

  ngOnInit() {
    this.userService.getUsers().subscribe({
      next: (data) => {
        this.users.set(data);
        this.isLoading.set(false);
      },
      error: (err) => {
        console.error(err);
        this.isLoading.set(false);
      }
    });
  }
}
Méthodes CRUD : 
// GET - Lire
http.get<User[]>('/api/users')
http.get<User>('/api/users/1')

// POST - Créer
http.post<User>('/api/users', {

Avec options :

// URL : /api/users?skip=10&limit=20
Avec catchError : 
import { catchError, throwError } from 'rxjs';

getUsers(): Observable<User[]> {
  return this.http.get<User[]>(this.apiUrl).pipe(
    catchError(this.handleError)
  );
}

private handleError(error: HttpErrorResponse) {
  let message = 'Une erreur est survenue';

  if (error.error instanceof ErrorEvent) {
    // Erreur client (réseau, etc.)
    message = `Erreur: ${error.error.message}`;
  } else {
    // Erreur serveur
    message = `Code ${error.status}: ${error.message}`;
  }

  console.error(message);
  return throwError(() => new Error(message));
}
Dans le composant : 
this.userService.getUsers().subscribe({
  next: (data) => {
    this.users.set(data);
  },
  error: (err) => {
    this.errorMessage.set(err.message);
    console.error(err);
  }
});

Un intercepteur modifie globalement toutes les requêtes et/ou réponses HTTP.

Cas d'usage :
  • Ajouter un token d'authentification
  • Logger les requêtes
  • Gérer les erreurs globalement
  • Ajouter des headers communs
  • Afficher un loader
Exemple - Intercepteur d'authentification : 
import { HttpInterceptorFn } from '@angular/common/http';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const authService = inject(AuthService);
  const token = authService.getToken();

  // Ajouter le token à la requête
  if (token) {
    req = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`
      }
    });
  }

  return next(req);
};
Enregistrer l'intercepteur : 
// main.ts
import { provideHttpClient, withInterceptors } from '@angular/common/http';

bootstrapApplication(AppComponent, {
  providers: [
    provideHttpClient(
      withInterceptors([authInterceptor])
    )
  ]
});
💡 Note : L'intercepteur s'applique automatiquement à TOUTES les requêtes HTTP de l'application.
Retry simple : 
import { retry } from 'rxjs/operators';

getUsers(): Observable<User[]> {
  return this.http.get<User[]>(this.apiUrl).pipe(
    retry(3), // Réessaie 3 fois en cas d'erreur
    catchError(this.handleError)
  );
}
Retry avec délai exponentiel : 
import { retry, timer } from 'rxjs';

getUsers(): Observable<User[]> {
  return this.http.get<User[]>(this.apiUrl).pipe(
    retry({
      count: 3,
      delay: (error, retryCount) => {
        console.log(`Tentative ${retryCount}`);
        // Délai exponentiel : 2s, 4s, 8s
        return timer(Math.pow(2, retryCount) * 1000);
      }
    }),
    catchError(this.handleError)
  );
}
⚠️ Attention : N'utilisez retry que pour les erreurs temporaires (timeout, 503). Pas pour 404 ou 401 !

Une nouvelle API déclarative pour simplifier les requêtes HTTP avec gestion automatique du loading et des erreurs.

Sans Resource (approche traditionnelle) : 
@Component({...})
export class UsersComponent implements OnInit {
  users = signal<User[]>([]);
  isLoading = signal(true);
  error = signal<string | null>(null);

  ngOnInit() {
    this.http.get<User[]>('/api/users').subscribe({
      next: (data) => {
        this.users.set(data);
        this.isLoading.set(false);
      },
      error: (err) => {
        this.error.set(err.message);
        this.isLoading.set(false);
      }
    });
  }
}
Avec Resource (moderne) : 
import { resource } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class UserService {
  private http = inject(HttpClient);

  // ✅ Resource déclarative
  users = resource({
    loader: () => this.http.get<User[]>('/api/users')
  });
}

// Composant - beaucoup plus simple !
@Component({...})
export class UsersComponent {
  userService = inject(UserService);

  // Accès direct aux données
  template: `
    @if (userService.users.isLoading()) {
      <p>Chargement...</p>
    } @else if (userService.users.error()) {
      <p>Erreur: {{ userService.users.error().message }}</p>
    } @else {
      @for (user of userService.users.value(); track user.id) {
        <li>{{ user.nom }}</li>
      }
    }
  `
}
Resource avec paramètre réactif : 
searchResults = resource({
  request: () => ({ term: this.searchTerm() }),
  loader: ({ request }) =>
    this.http.get(`/api/search?q=${request.term}`)
});

// Quand searchTerm() change → rechargement automatique !
✅ Avantages :
  • Moins de code boilerplate
  • Gestion auto du loading/error
  • Réactivité intégrée
  • Plus déclaratif
🔐 PARTIE 3 : AUTHENTIFICATION
1. Service d'authentification : 
@Injectable({ providedIn: 'root' })
export class AuthService {
  private http = inject(HttpClient);
  private router = inject(Router);
  
  private tokenSignal = signal<string | null>(null);
  
  isAuthenticated = computed(() => !!this.tokenSignal());

  constructor() {
    // Charger le token depuis localStorage
    const token = localStorage.getItem('auth_token');
    if (token) {
      this.tokenSignal.set(token);
    }
  }

  login(email: string, password: string): Observable<LoginResponse> {
    return this.http.post<LoginResponse>('/api/login', {
      email,
      password
    }).pipe(
      tap(response => {
        this.tokenSignal.set(response.token);
        localStorage.setItem('auth_token', response.token);
      })
    );
  }

  logout(): void {
    this.tokenSignal.set(null);
    localStorage.removeItem('auth_token');
    this.router.navigate(['/login']);
  }

  getToken(): string | null {
    return this.tokenSignal();
  }
}
2. Intercepteur pour ajouter le token :

1. Vérifier l'expiration du token : 
import { jwtDecode } from 'jwt-decode';

isTokenExpired(token: string): boolean {
  try {
    const decoded: any = jwtDecode(token);
    const now = Date.now() / 1000;
    return decoded.exp < now;
  } catch {
    return true;
  }
}

isAuthenticated(): boolean {
  const token = this.getToken();
  return token !== null && !this.isTokenExpired(token);
}
2. Intercepteur pour gérer 401 : 
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const authService = inject(AuthService);
  const router = inject(Router);

  return next(req).pipe(
    catchError((error: HttpErrorResponse) => {
      if (error.status === 401) {
        // Token expiré ou invalide
        authService.logout();
        router.navigate(['/login']);
      }
      return throwError(() => error);
    })
  );
};
3. Refresh token (optionnel) : 
refreshToken(): Observable<TokenResponse> {
  const refreshToken = localStorage.getItem('refresh_token');
  
  return this.http.post<TokenResponse>('/api/refresh', {
    refreshToken
  }).pipe(
    tap(response => {
      this.tokenSignal.set(response.token);
      localStorage.setItem('auth_token', response.token);
    })
  );
}
⚡ PARTIE 4 : SSR & PERFORMANCE

Le SSR rend l'application sur le serveur avant de l'envoyer au navigateur.

Sans SSR (CSR - Client-Side Rendering) : 
1. Navigateur télécharge app.js
2. Angular démarre
3. Affiche le contenu
→ Délai de 1-3 secondes (page blanche)
Avec SSR : 
1. Serveur génère le HTML
2. Navigateur affiche immédiatement
3. Angular hydrate (rend interactif)
→ Contenu visible en <500ms
Avantages :
  • ✅ SEO optimal (Google voit le contenu)
  • ✅ Temps de premier affichage rapide
  • ✅ Meilleur sur mobile
  • ✅ Social media previews
Inconvénients :
  • ❌ Infrastructure serveur nécessaire
  • ❌ Plus complexe
  • ❌ Coût serveur
// Activer SSR
ng add @angular/ssr

// main.server.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { provideServerRendering } from '@angular/platform-server';

export default bootstrapApplication(AppComponent, {
  providers: [
    provideServerRendering()
  ]
});

L'hydration est le processus qui rend interactif le HTML généré par SSR.

Hydration classique :
  • Tout le HTML regeneré côté client
  • Flash de contenu
  • Gaspillage de ressources
Hydration progressive (Angular 16+) :
  • Réutilise le HTML du serveur
  • Pas de flash
  • Plus performant
// Activer l'hydration progressive
import { provideClientHydration } from '@angular/platform-browser';

bootstrapApplication(AppComponent, {
  providers: [
    provideClientHydration()
  ]
});
✅ Résultat : Transition fluide du serveur au client, pas de re-render, meilleures performances.
✨ PARTIE 5 : BONNES PRATIQUES
Structure recommandée : 
src/app/
├── app.routes.ts          # Routes principales
├── routes/
│   ├── admin.routes.ts    # Routes admin (lazy)
│   ├── blog.routes.ts     # Routes blog (lazy)
│   └── shop.routes.ts     # Routes shop (lazy)
├── pages/
│   ├── home/
│   ├── about/
│   └── not-found/
└── guards/
    ├── auth.guard.ts
    └── unsaved.guard.ts
Règles :
  • Routes publiques au root
  • Sections complexes en lazy loading
  • Guards dans un dossier séparé
  • Wildcard en dernier
// app.routes.ts
export const routes: Routes = [
  { path: '', redirectTo: 'home', pathMatch: 'full' },
  { path: 'home', component: HomeComponent },
  { path: 'about', component: AboutComponent },
  
  // Lazy loading
  {
    path: 'admin',
    loadChildren: () => import('./routes/admin.routes')
                        .then(m => m.adminRoutes),
    canActivate: [authGuard]
  },
  {
    path: 'blog',
    loadChildren: () => import('./routes/blog.routes')
                        .then(m => m.blogRoutes)
  },
  
  // Catch-all en dernier
  { path: '**', component: NotFoundComponent }
];
Utilisez Resource quand :
  • ✅ Requêtes simples GET
  • ✅ Besoin de loading/error automatique
  • ✅ Données réactives
  • ✅ Composant qui affiche directement
Utilisez HttpClient classique quand :
  • ✅ POST/PUT/DELETE (mutations)
  • ✅ Logique complexe
  • ✅ Transformations de données
  • ✅ Chaining d'opérateurs RxJS
// ✅ Resource - parfait pour afficher des données
users = resource({
  loader: () => this.http.get<User[]>('/api/users')
});

// ✅ HttpClient - parfait pour les mutations
createUser(user: User): Observable<User> {
  return this.http.post<User>('/api/users', user).pipe(
    tap(() => this.users.reload()),
    catchError(this.handleError)
  );
}
💡 Conseil : Combinez les deux ! Resource pour lire, HttpClient pour modifier.
