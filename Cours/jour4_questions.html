Questions & Réponses - Tests & Production

📋 PARTIE 1 : TESTS ET QUALITÉ
Karma (Legacy) :
  • Lanceur de tests traditionnel d'Angular
  • Démarre un serveur + navigateur Chrome
  • Temps d'exécution : 5-10 secondes
  • Stable et bien documenté
Vitest (Moderne) :
  • Lanceur moderne basé sur Vite
  • Exécution ultra-rapide (1-2 secondes)
  • Support HMR (rechargement en direct)
  • Interface graphique incluse
  • Recommandé pour Angular 17+
✅ À retenir : Vitest est plus rapide et moderne. Utiliser Vitest pour les nouveaux projets Angular 17+.
Utiliser provideHttpClientTesting() : 
TestBed.configureTestingModule({
  providers: [
    TodoService,
    provideHttpClient(),
    provideHttpClientTesting()
  ]
});

const httpMock = TestBed.inject(HttpTestingController);
const req = httpMock.expectOne('/api/todos');
req.flush(mockData);
httpMock.verify();
Étapes :
  1. Configurer avec provideHttpClientTesting()
  2. Injecter HttpTestingController
  3. Utiliser expectOne() pour capturer la requête
  4. Utiliser flush() pour répondre
  5. Utiliser verify() pour vérifier pas de requête orpheline
⚠️ Important : Utilisez provideHttpClientTesting() (moderne) et non HttpClientTestingModule (deprecated).
Espionner et vérifier l'événement : 
// Espionner l'événement
spyOn(component.bascule, 'emit');

// Déclencher l'action
button.click();

// Vérifier
expect(component.bascule.emit).toHaveBeenCalled();
expect(component.bascule.emit).toHaveBeenCalledWith(42);
Vérifications possibles :
  • toHaveBeenCalled() : a été appelé au moins une fois
  • toHaveBeenCalledTimes(n) : a été appelé exactement n fois
  • toHaveBeenCalledWith(arg) : a été appelé avec cet argument
💡 Conseil : Toujours tester les @Output() avec des spies pour vérifier que les événements sont émis.
Utiliser fakeAsync + tick : 
it('doit gérer les délais', fakeAsync(() => {
  let result = '';
  setTimeout(() => {
    result = 'fait';
  }, 1000);

  tick(1000); // Avancer le temps de 1000ms
  expect(result).toBe('fait');
}));
Autres approches :
  • fakeAsync(() => { tick(500); }) : avancer le temps
  • flush() : exécuter tous les timers
  • done callback : (old style) appeler done() quand prêt
✅ Best Practice : Utiliser fakeAsync + tick pour un code clair et prévisible.
Objectifs minimums :
  • Statements : ≥ 80% de lignes exécutées
  • Branches : ≥ 75% de chemins de code
  • Functions : ≥ 80% de fonctions testées
  • Lines : ≥ 80% de lignes testées
Générer le rapport : 
ng test --code-coverage --no-watch
# Ouvrir coverage/index.html
⚠️ Important : 80% est un minimum. Plus la couverture, mieux c'est, mais pas d'obsession - viser qualité plutôt que quantité.
🚀 PARTIE 2 : DÉPLOIEMENT & PRODUCTION
Optimisations automatiques (build production) :
  • AOT : Compilation Ahead-Of-Time
  • Tree-shaking : Supprime code inutilisé
  • Minification : Compresse le code
  • Code splitting : Lazy loading
Résultat typique :
  • Avant production : ~500 KB
  • Après production : ~100-150 KB (gzippé)
  • Compression : 70-80% du bundle initial
ng build --configuration production
💡 Analyser : Utilisez webpack-bundle-analyzer pour visualiser le bundle.
Trois métriques critiques :
  • LCP (Largest Contentful Paint) : < 2.5s - affichage du contenu principal
  • INP (Interaction to Next Paint) : < 200ms - réactivité (remplace FID)
  • CLS (Cumulative Layout Shift) : < 0.1 - stabilité visuelle
Tester avec Lighthouse : 
DevTools → Lighthouse → Generate report
# Vérifier Performance ≥ 90
⚠️ Critique : Les Core Web Vitals impactent le classement SEO. Ne pas négliger !
Options principales :
  • Netlify : Gratuit, simple, recommandé ⭐
  • GitHub Pages : Gratuit, mais limité
  • Vercel : Gratuit, similaire à Netlify
  • Nginx (VPS) : Complet, mais plus complexe
  • Docker : Containerization
Déploiement Netlify (le plus simple) : 
ng build --configuration production
npm install -g netlify-cli
netlify deploy --prod --dir dist
# URL : https://votre-app.netlify.app
✅ Recommandé : Netlify pour 90% des cas. C'est simple, rapide et gratuit.
Quatre principes :
  1. Perceptible : Visible, audible (images alt, couleurs, contraste)
  2. Opérable : Clavier, navigation (tabulation, focus visible)
  3. Compréhensible : Clair, prévisible (structure hiérarchique)
  4. Robuste : Compatible (HTML valide, ARIA correcte)
Vérifications essentielles :
  • Alt text sur les images
  • Navigation au clavier complète
  • ARIA labels sur les inputs
  • Contraste texte/fond ≥ 4.5:1
  • Lecteurs d'écran testés
Lighthouse → Accessibility ≥ 90
⚠️ Légal : WCAG 2.1 est obligatoire dans beaucoup de pays/secteurs. Pas optional !
Fichier .github/workflows/deploy.yml : 
name: Build & Deploy

on:
  push:
    branches: [main]

jobs:
  build-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm ci
      - run: npm run test -- --no-watch --code-coverage
      - run: npm run build -- --configuration production
      - name: Deploy to Netlify
        uses: nwtgck/actions-netlify@v2
        with:
          publish-dir: './dist'
        env:
          NETLIFY_AUTH_TOKEN: ${{ secrets.NETLIFY_AUTH_TOKEN }}
          NETLIFY_SITE_ID: ${{ secrets.NETLIFY_SITE_ID }}
Flux :
  1. Push code sur main
  2. Tests automatiques
  3. Build production
  4. Déploiement Netlify
✅ Avantage : Zéro manipulation manuelle. Déploiement automatique à chaque commit.
