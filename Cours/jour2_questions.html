Questions & Réponses - Réactivité & Composants Avancés

🌊 PARTIE 1 : PROGRAMMATION RÉACTIVE & RxJS
Impératif :
  • On décrit comment faire étape par étape
  • Les changements ne se propagent pas automatiquement
  • Exemple : let c = a + b; a = 20; // c reste inchangé
Déclaratif (Réactif) :
  • On décrit quoi faire, le système gère le comment
  • Les changements se propagent automatiquement
  • Exemple avec Signals : c = computed(() => a() + b()); a.set(20); // c se met à jour !
✅ Avantage : Code plus prévisible, moins d'erreurs, meilleure réactivité UI.

Une séquence d'événements ou de valeurs qui se produisent dans le temps, qu'on peut observer et transformer.

Exemple concret : 
Utilisateur tape "a" (temps 0ms)
    ↓
Utilisateur tape "n" (temps 100ms)
    ↓
Utilisateur tape "g" (temps 200ms)
    ↓
Flux d'événements : ["a", "an", "ang"]
    ↓
Application réagit après 300ms d'inactivité
Types de flux :
  • Clics sur un bouton : button.click$
  • Valeurs d'un input : input.valueChanges$
  • Réponses HTTP : http.get('/users')$
Promesse :
  • Émet une seule valeur
  • Non annulable
  • Exécution immédiate
  • Usage : requêtes HTTP simples
Observable :
  • Émet plusieurs valeurs dans le temps
  • Annulable avec unsubscribe()
  • Exécution lazy (démarre au subscribe)
  • Usage : événements, streams, WebSockets
// Promesse
new Promise(resolve => resolve('Valeur'));

// Observable
new Observable(observer => {
  observer.next('Valeur 1');
  observer.next('Valeur 2');
  observer.next('Valeur 3');
});
Cold Observable :
  • Commence à émettre uniquement quand on s'abonne
  • Chaque souscription reçoit des valeurs indépendantes
  • Exemple : requête HTTP, intervalle créé à la souscription
Hot Observable :
  • Émet des valeurs indépendamment des souscriptions
  • Les abonnés partagent le flux
  • Exemple : Subject, événements DOM, WebSocket
// Cold - valeurs différentes
const cold$ = new Observable(obs => obs.next(Math.random()));
cold$.subscribe(val => console.log('Sub 1:', val)); // 0.456
cold$.subscribe(val => console.log('Sub 2:', val)); // 0.789

// Hot - valeur partagée
const hot$ = new Subject();
hot$.subscribe(val => console.log('Sub 1:', val));
hot$.subscribe(val => console.log('Sub 2:', val));
hot$.next(1); // Les deux affichent 1
💡 Astuce : Si vous voyez new Observable(), c'est cold. Si c'est un Subject, c'est hot.

Attend 300ms d'inactivité avant d'émettre la dernière valeur.

Cas d'usage principal :
  • Recherche en temps réel (éviter trop de requêtes)
  • Validation de formulaire (attendre que l'utilisateur finisse de taper)
  • Auto-save (sauvegarder après inactivité)
searchControl.valueChanges.pipe(
  debounceTime(300),  // Attend 300ms après la dernière frappe
  distinctUntilChanged()  // Ignore si même valeur
).subscribe(term => {
  // Faire la recherche
});
✅ Résultat : Si l'utilisateur tape "angular" rapidement, une seule recherche est lancée (pas 7).
map :
  • Transforme chaque valeur (synchrone)
  • Retourne une valeur simple
  • Exemple : map(x => x * 2)
switchMap :
  • Transforme en un nouvel Observable
  • Annule l'Observable précédent
  • Idéal pour les requêtes HTTP successives
// map : transformation simple
source$.pipe(
  map(x => x * 2)
).subscribe(console.log);

// switchMap : requêtes HTTP
searchInput$.pipe(
  debounceTime(300),
  switchMap(term => http.get(`/search?q=${term}`))
  // ⚠️ Si nouvelle recherche → annule la précédente
).subscribe(results => console.log(results));
⚠️ Important : switchMap évite les réponses désordonnées en annulant les anciennes requêtes.
3 méthodes :

1. Async Pipe (RECOMMANDÉ) :

// Template
<p>{{ data$ | async }}</p>

// Composant
data$ = this.service.getData();
// Pas de subscribe, pas de unsubscribe !

2. takeUntil avec Subject :

private destroy$ = new Subject<void>();

ngOnInit() {
  this.service.getData().pipe(
    takeUntil(this.destroy$)
  ).subscribe(data => this.data = data);
}

ngOnDestroy() {
  this.destroy$.next();
  this.destroy$.complete();
}

3. Array de Subscriptions :

private subs: Subscription[] = [];

ngOnInit() {
  const sub = this.service.getData().subscribe(...);
  this.subs.push(sub);
}

ngOnDestroy() {
  this.subs.forEach(sub => sub.unsubscribe());
}
✅ Best Practice : Utiliser l'async pipe partout où c'est possible.
⚡ PARTIE 2 : SIGNALS (API MODERNE)

Une valeur réactive synchrone qui notifie automatiquement ses dépendants quand elle change.

Caractéristiques :
  • Synchrone (pas d'async/await)
  • Détection de changements optimale
  • Lecture avec ()
  • Modification avec .set() ou .update()
import { signal } from '@angular/core';

// Créer
const count = signal(0);

// Lire
console.log(count()); // 0

// Modifier
count.set(5);
count.update(v => v + 1);

console.log(count()); // 6
💡 Nouveau en Angular 16+ : Les Signals sont l'avenir de la réactivité dans Angular.
signal() :
  • Valeur modifiable manuellement
  • Utilise .set() ou .update()
  • Source de vérité
computed() :
  • Valeur dérivée readonly
  • Se recalcule automatiquement quand dépendances changent
  • Memoïsée (pas de recalcul inutile)
// signal - modifiable
const count = signal(0);
count.set(5);

// computed - dérivé
const double = computed(() => count() * 2);
console.log(double()); // 10

count.set(10);
console.log(double()); // 20 (mis à jour automatiquement !)
✅ Règle : signal() pour l'état, computed() pour les valeurs dérivées.

Exécute des effets de bord quand les signals dont il dépend changent.

Cas d'usage :
  • Logging / debugging
  • Sauvegarder dans localStorage
  • Synchroniser avec une API externe
  • Analytics / tracking
import { effect } from '@angular/core';

const count = signal(0);

// Effect s'exécute à chaque changement
effect(() => {
  console.log('Count changed:', count());
  localStorage.setItem('count', count().toString());
});

count.set(5); // Log + localStorage automatiquement !
⚠️ Attention : N'utilisez pas effect() pour du logic métier. Préférez computed() pour les calculs.
Observable (RxJS) :
  • Asynchrone
  • Flux de valeurs dans le temps
  • Nécessite subscribe()
  • Idéal pour : HTTP, WebSocket, événements
Signal :
  • Synchrone
  • Valeur d'état réactive
  • Lecture directe avec ()
  • Idéal pour : état local, données UI
// Observable - asynchrone
const data$ = http.get('/api/users');
data$.subscribe(users => console.log(users));

// Signal - synchrone
const users = signal<User[]>([]);
console.log(users()); // Accès immédiat
✅ Ils se complètent : Signals pour l'état, Observables pour l'asynchrone.
Signal → Observable : 
import { toObservable } from '@angular/core/rxjs-interop';

const count = signal(0);
const count$ = toObservable(count);

count$.subscribe(val => console.log('Changed:', val));
Observable → Signal : 
import { toSignal } from '@angular/core/rxjs-interop';
import { interval } from 'rxjs';

const time$ = interval(1000);
const timeSignal = toSignal(time$, { initialValue: 0 });

console.log(timeSignal()); // 0, 1, 2, 3...
💡 Usage : Utilisez toSignal pour transformer les Observables RxJS en Signals dans vos composants.
🚀 PARTIE 3 : MODE ZONELESS & PERFORMANCES

Une bibliothèque qui intercepte tous les événements asynchrones (timers, événements DOM, HTTP, etc.) pour déclencher automatiquement la détection de changements.

Fonctionnement : 
// Zone.js intercepte TOUT
setTimeout(() => { ... })      → Détection
button.click()                 → Détection
http.get('/api')              → Détection
Promise.then()                → Détection
Avantages :
  • Détection automatique partout
  • Pas besoin de déclencher manuellement
Inconvénients :
  • Performances réduites
  • Bugs occasionnels
  • Bundle size augmenté
Performances :
  • +30% à +50% plus rapide
  • Moins de vérifications de changements
  • Bundle plus léger (~10 KB économisés)
Qualité du code :
  • Plus prévisible
  • Meilleure gestion mémoire
  • Supprime les bugs Zone.js
// Activer Zoneless
bootstrapApplication(AppComponent, {
  providers: [
    provideExperimentalZonelessChangeDetection()
  ]
});
✅ Recommandé : Activez le mode Zoneless pour tous les nouveaux projets Angular 17+.

Uniquement via 3 mécanismes :

1. Signals : 
count.set(5);           // ✅ Déclenche détection
count.update(v => v + 1); // ✅ Déclenche détection
2. Async Pipe : 
<p>{{ data$ | async }}</p> 
// ✅ Détection automatique
3. Événements DOM : 
<button (click)="onClick()">Click</button>
// ✅ Détection au clic
⚠️ Important : 
// ❌ Ne déclenche PAS de détection en Zoneless
setTimeout(() => {
  this.count++; // Mutation directe
}, 1000);

// ✅ Déclenche la détection
count = signal(0);
setTimeout(() => {
  this.count.set(this.count() + 1); // Signal
}, 1000);
🛠️ PARTIE 4 : SERVICES & INJECTION DE DÉPENDANCES
Responsabilités :
  • Logique métier : Calculs, transformations
  • Partage de données : Entre composants
  • Requêtes HTTP : API calls
  • État global : Store, cache
@Injectable({ providedIn: 'root' })
export class UserService {
  private users = signal<User[]>([]);
  readonly usersList = this.users.asReadonly();

  addUser(user: User) {
    this.users.update(users => [...users, user]);
  }

  loadUsers() {
    return this.http.get<User[]>('/api/users');
  }
}
✅ Règle d'or : Composants = Présentation. Services = Logique métier.

Le service est un singleton global fourni au niveau de l'application entière.

Comportement :
  • Une seule instance pour toute l'application
  • Partagée par tous les composants
  • Disponible immédiatement
  • Tree-shakable (supprimé si non utilisé)
@Injectable({ providedIn: 'root' })
export class MyService {
  // Une seule instance globale
}
💡 Best Practice : Utilisez providedIn: 'root' pour 90% de vos services.

Angular a plusieurs niveaux d'injecteurs qui forment une hiérarchie :

┌─────────────────┐
│   ROOT          │ ← providedIn: 'root' (singleton global)
└────────┬────────┘
         │
    ┌────▼─────┐
    │  MODULE  │ ← Module provider
    └────┬─────┘
         │
    ┌────▼─────┐
    │COMPONENT │ ← Component provider (instance locale)
    └──────────┘
Résolution :

Angular cherche le service du bas vers le haut :

  1. Composant actuel
  2. Composant parent
  3. Module
  4. Root
// Service global
@Injectable({ providedIn: 'root' })
export class GlobalService { }

// Service local (nouvelle instance par composant)
@Component({
  providers: [LocalService]
})
export class MyComponent { }
💬 PARTIE 5 : COMMUNICATION ENTRE COMPOSANTS
1. @Input() : Parent → Enfant 
// Enfant
@Input() message!: string;

// Parent
<app-enfant [message]="'Hello'"></app-enfant>
2. @Output() : Enfant → Parent 
// Enfant
@Output() clicked = new EventEmitter<string>();
this.clicked.emit('Data');

// Parent
<app-enfant (clicked)="onClicked($event)"></app-enfant>
3. Service : Frères/Éloignés 
@Injectable({ providedIn: 'root' })
export class MessageService {
  private subject = new Subject<string>();
  message$ = this.subject.asObservable();

  send(msg: string) {
    this.subject.next(msg);
  }
}
@Input() (Ancien) :
  • Décorateur classique
  • Pas réactif nativement
  • Angular < 17
input() (Nouveau - Signal) :
  • API Signal native
  • Plus performant
  • Permet computed() basés sur inputs
  • Angular 17+
// ❌ Ancien
@Input() age!: number;

// ✅ Nouveau (recommandé)
age = input.required<number>();
estMajeur = computed(() => this.age() >= 18);
✅ Recommandation : Utilisez input() pour tous les nouveaux projets Angular 17+.
♻️ PARTIE 6 : CYCLE DE VIE DES COMPOSANTS
Ordre d'exécution :
  1. ngOnInit - Initialisation
  2. ngOnChanges - Changement d'inputs
  3. ngDoCheck - Détection personnalisée
  4. ngAfterViewInit - Vue initialisée
  5. ngAfterContentInit - Contenu initialisé
  6. ngOnDestroy - Avant destruction
export class MyComponent implements OnInit, OnDestroy {
  ngOnInit() {
    // Initialisation, appels API, souscriptions
  }

  ngOnDestroy() {
    // Nettoyage, unsubscribe, clearInterval
  }
}
💡 Les plus utilisés : ngOnInit (90%) et ngOnDestroy (cleanup).
constructor() :
  • Injection de dépendances uniquement
  • Le composant n'est pas encore prêt
  • Pas d'accès aux inputs/outputs
  • Pas d'accès au DOM
ngOnInit() :
  • Initialisation complète
  • Inputs disponibles
  • Idéal pour appels API
  • Idéal pour souscriptions
// ❌ Mauvais
constructor(private http: HttpClient) {
  this.http.get('/api/users').subscribe(...); // Trop tôt !
}

// ✅ Bon
ngOnInit() {
  this.http.get('/api/users').subscribe(...);
}
⚠️ Règle : Constructor = injection. ngOnInit = logique.
📝 PARTIE 7 : FORMULAIRES RÉACTIFS
Template-Driven (ancien) :
  • Logique dans le template avec [(ngModel)]
  • Moins testable
  • Moins prévisible
  • Validation limitée
Reactive Forms (recommandé) :
  • Logique en TypeScript
  • Plus testable
  • Plus prévisible
  • Validation complexe facile
  • Observables (valueChanges)
// ❌ Template-Driven
<input [(ngModel)]="email" required>

// ✅ Reactive Forms
emailControl = new FormControl('', [
  Validators.required,
  Validators.email
]);

<input [formControl]="emailControl">
✅ Recommandation : Toujours utiliser Reactive Forms.
Validateurs courants :
  1. Validators.required - Champ obligatoire
  2. Validators.email - Format email
  3. Validators.minLength(n) - Longueur minimale
  4. Validators.maxLength(n) - Longueur maximale
  5. Validators.min(n) - Valeur minimale (nombre)
  6. Validators.max(n) - Valeur maximale
  7. Validators.pattern(regex) - Expression régulière
email = new FormControl('', [
  Validators.required,
  Validators.email
]);

age = new FormControl(0, [
  Validators.required,
  Validators.min(18),
  Validators.max(100)
]);

password = new FormControl('', [
  Validators.required,
  Validators.minLength(8),
  Validators.pattern(/^(?=.*[A-Z])/)
]);
Structure : 
export function ageMinValidator(min: number): ValidatorFn {
  return (control: AbstractControl): ValidationErrors | null => {
    if (!control.value) return null; // Ne valide pas si vide
    
    if (control.value < min) {
      return { 
        ageMin: { 
          requiredAge: min, 
          actualAge: control.value 
        } 
      };
    }
    
    return null; // Valide
  };
}
Utilisation : 
age = new FormControl(0, [
  Validators.required,
  ageMinValidator(18)
]);

// Template
@if (age.errors?.['ageMin']) {
  <p>Vous devez avoir au moins 
     {{ age.errors?.['ageMin'].requiredAge }} ans</p>
}
💡 Retour : ValidationErrors (objet) si invalide, null si valide.
valueChanges :

Observable qui émet à chaque changement de valeur

searchControl.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged()
).subscribe(term => {
  // Faire la recherche
});
statusChanges :

Observable qui émet à chaque changement de statut (VALID, INVALID, PENDING)

form.statusChanges.subscribe(status => {
  console.log(status); // 'VALID' | 'INVALID' | 'PENDING'
  
  if (status === 'VALID') {
    this.enableSubmit = true;
  }
});
✅ Usage : valueChanges pour la recherche réactive, statusChanges pour activer/désactiver des boutons.
✨ PARTIE 8 : BONNES PRATIQUES
✅ DANS LE SERVICE :
  • Logique métier et calculs
  • Appels API
  • Transformations de données
  • État partagé
✅ DANS LE COMPOSANT :
  • Présentation uniquement
  • Gestion du template
  • Événements UI
  • Navigation
// ❌ Mauvais - logique dans le composant
export class UserComponent {
  calculateTotal(users: User[]) {
    return users.reduce((sum, u) => sum + u.value, 0);
  }
}

// ✅ Bon - logique dans le service
@Injectable({ providedIn: 'root' })
export class UserService {
  readonly total = computed(() => 
    this.users().reduce((sum, u) => sum + u.value, 0)
  );
}
✅ Règle d'or : Composants légers, services intelligents.
Avantages de l'async pipe :
  • ✅ Gère subscribe/unsubscribe automatiquement
  • ✅ Pas de fuites mémoire
  • ✅ Code plus propre et déclaratif
  • ✅ Moins de code boilerplate
  • ✅ Détection de changements optimale
// ❌ Mauvais
users: User[] = [];
private sub!: Subscription;

ngOnInit() {
  this.sub = this.service.getUsers().subscribe(
    users => this.users = users
  );
}

ngOnDestroy() {
  this.sub.unsubscribe();
}

// ✅ Bon
users$ = this.service.getUsers();

// Template
<div *ngFor="let user of users$ | async">
  {{ user.name }}
</div>
✅ Best Practice : Utilisez l'async pipe partout où c'est possible.
Subject :
  • Pas de valeur initiale
  • Nouveaux abonnés ne reçoivent que les futures valeurs
  • Usage : Événements, notifications
BehaviorSubject :
  • Valeur initiale obligatoire
  • Nouveaux abonnés reçoivent immédiatement la dernière valeur
  • Usage : État, données actuelles
// Subject - pour événements
const clicked = new Subject<void>();
clicked.next(); // Émission

// BehaviorSubject - pour état
const count = new BehaviorSubject(0);
console.log(count.getValue()); // 0
count.next(5);
count.subscribe(val => console.log(val)); // 5 immédiatement !
💡 Règle : État actuel = BehaviorSubject. Événements = Subject.

Réponse : input() (Signal)

Raisons :
  • ✅ Plus performant
  • ✅ Réactif nativement
  • ✅ S'intègre avec computed()
  • ✅ Futur d'Angular
  • ✅ Moins de code boilerplate
// ❌ Ancien (@Input)
@Input() age!: number;
estMajeur!: boolean;

ngOnChanges() {
  this.estMajeur = this.age >= 18;
}

// ✅ Nouveau (input Signal)
age = input.required<number>();
estMajeur = computed(() => this.age() >= 18);
✅ Migration : Commencez par input() pour nouveaux composants, migrez progressivement les anciens.
